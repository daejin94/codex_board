## Commit Guide

### Commit Message Rule
|타입|설명|
|---|---|
|Feat|새로운 기능 추가|
|Fix|버그 or 기능 수정|
|Design|CSS 등 사용자 UI 디자인 수정|
|Style|코드 포맷 변경, 코드 수정 없는 경우|
|Refactor|코드 리팩토링|
|Comment|필요한 주석 추가 및 변경|
|Docs|문서 수정한 경우|
|Rename|파일이나 폴더명을 수정하거나 경로 수정했을 경우|
|Remove|파일을 삭제했을 경우|
|Build|	빌드 관련 버전명 등 수정(코드 변경X)|
|Etc|위 어느 타입에도 해당안되는 경우|

### Commit Message Structure

#### <제목>

[타입] <제목>
- 필수항목
- 50자를 넘기지 않음
- 명령형, 현재 시제 사용하며 명사형으로 마침
- 어떻게 보다 무엇과 왜를 설명

#### <본문>

1. <본문 내용>
- 선택사항이며 필수 작성은 아님
- 본문의 각 행은 70자를 넘기지 않음
- 명령형, 현재 시제 사용하며 명사형으로 마침

**🔥 커밋 타입 예시**
<<제목>>
[Feat] 사용자 회원가입 기능 구현

<<본문>>
1. 이메일, 비밀번호 입력 추가
2. 회원가입 완료 시 환영 이메일 발송

**📋 주의사항**
- 한 커밋에 복수의 성격이나 기능 수정사항을 포함시키지 말것
<예시> [Feat] 회원가입 기능, 유저프로필 변경 기능 구현(X)
